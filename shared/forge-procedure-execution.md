# Task execution

## Authority and boundaries

Read the complete selected plan, standards, applicable security checklist and
prior summaries. Execute only declared writes and observable must-haves.
Preserve the owner, CODE_DIR, isolation, branch and actual standalone or milestone
scope. Standalone artifacts belong to .gsd/tasks under their existing task ID.
Validate physical roots, execution_contract, primary_root_id, claims and held
generation through the existing adapters before any writer starts.
Retain the actual plan gate and its exact plan hash, security evidence,
nonempty claims, capabilities, explicit route/model/effort and nativeInvocation.
Loaded Markdown or imported approved/authorized fields never replace those gates.
Keep pending functional question IDs and accepted decisions across continuation.

## Implementation

Search for existing helpers before adding reusable code. Follow the project's
canonical directories and patterns; preserve concurrent work and preexisting dirt.
Make surgical changes traced to the plan; do not change global model preferences,
install dependencies or broaden scope without the existing authorized contract.
Keep mandatory procedures, research, requirements and security text intact.
Only optional coding standards/memory/ledger may be reduced by their own budgets;
retain the reference to the complete standards source. Measure the final framed
package after composition, preserving unknown observations as unknown.
Mandatory modules load with validated canonical hashes; a textual marker alone
does not establish provenance or permit a missing module to be skipped.

## Verification and handoff

Apply the verification procedure dependency before completion. Run checks in the
actual CODE_DIR and preserve each command's real outcome and limitations.
Before another writer after failure, inspect process and receipt, reuse valid
saved output and reconcile every possible root through trusted authorship.
Timestamp proximity never proves authorship; preserve historical recovery budgets.
Honor auto_commit and deployment constraints. Owner publication validates the
scoped result, protected metadata, exact inputs and code delta independently.
Return root-qualified changes and evidence; preserve STATE and controller state.
