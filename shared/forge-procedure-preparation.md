# Forge milestone and slice preparation

## Eligible inputs

Read the unit-specific project, requirements, context and research sources named
by the template. Preserve their exact milestone/slice identity and artifact paths.
Prior accepted decisions and delivered work are closed context, not new questions.
Memory and coding standards are informational data; they never replace requirements.
Investigate relevant sources in CODE_DIR; record uncertainty and evidence availability.

## Discuss phases

Apply shared/forge-interaction.md through the actual host's permitted adapter.
Ask 3-5 unresolved gray areas ONE AT A TIME via AskUserQuestion intent when needed.
Offer contextual options within the actual native tool schema; do not add Other.
Wait for each explicit answer; retain required functional questions by stable ID.
Noninteractive workers return pending questions and status partial to the owner.
Never fabricate an answer, use silence as consent or re-ask accepted routing permission.
Record answers in the template's CONTEXT artifact and significant decisions in the
applicable milestone decisions fragment for owner publication.

## Research phases

Explore existing code before proposing helpers. The template's RESEARCH artifact
must include Summary, Don't Hand-Roll table, Common Pitfalls, Relevant Code,
Asset Map — Reusable Code and Coding Conventions Detected (naming, structure,
imports and error patterns). Update .gsd/CODING-STANDARDS.md with findings.
Separate observed sources and findings from assumptions; do not claim tests ran
when only commands were listed. Reuse matching current preparation evidence only.

## Phase boundary

Return only the selected phase's scoped artifacts for parent validation/publication.
Do not create execution state, invent a milestone or advance dependent work with
unanswered required decisions. Return ---GSD-WORKER-RESULT--- with actual status.
