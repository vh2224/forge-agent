# Canonical procedure distribution

Resolve the canonical source checkout before projecting either host. Inventory
the loader, closed schema, procedure manifest and every transitive module used
by all declared phases. Runtime copying and host Markdown projection are
different deliveries; a reference in a skill does not deliver its target.

Before writes, compose every declared phase with forge-procedure-context from
one trusted root. Validate core, dependencies, canonical UTF-8/LF hashes and
availability. A pending, missing, unreadable or modified mandatory module blocks
distribution before projection; never substitute empty informational context.

The project manifest selects the whole project root. If absent, the installed
Forge home is eligible. A present invalid or partial override never borrows
modules from another root. Preserve the matching manifest and module hashes.

Copy scripts, shared and schemas through the existing installer inventory.
Record the verified phase compositions and module hashes in the installation
manifest. Both host renderers load this distribution procedure before building
artifacts; generated boot instructions connect the installed loader to phases.

Use temporary fixture homes for installation and reinstallation validation.
Actual installation follows explicit user scope and authority for the selected
roots. Execute installed callers and builders, inspect actual composed content,
compare canonical hashes and repeated LF projections, and preserve frontmatter,
owned markers, operator files and preferences. Do not infer permission to probe
providers, change preferences or write outside the selected roots. Never execute
arbitrary consumer project JavaScript.

Keep implementation, temporary installation checks, CI, review, merge and human
acceptance independent. Offline synthetic fixtures prove only their exercised
contracts; they do not prove real provider operation, user acceptance or gains.
